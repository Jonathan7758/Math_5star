# design009.txt — 交互体验与答题设计深度分析

> 版本: v2.0-pre
> 日期: 2026-05-08
> 目的: 对标行业最佳实践，系统性分析启明星现有交互问题，指导 v2.0 重设计

# 第一部分：竞品对标分析

## 1.1 行业标杆对比

| 维度 | Prodigy Math | Duolingo Math | DragonBox | 启明星 v2.0 | 差距 |
|------|-------------|--------------|-----------|------------|------|
| **场景/故事** | RPG战斗+世界探索 | 线性关卡+角色陪伴 | 无文字图形化学习 | 纯答题卡片 | ❌ |
| **角色系统** | 自定义巫师Avatar换装 | 猫头鹰Duo+动画角色 | 可爱小怪兽 | 启小星5阶段SVG | ⚠️ |
| **动画质量** | Unity 3D引擎 | Lottie+自定义动画 | 2D骨骼动画 | CSS keyframe+Canvas | ❌ |
| **交互反馈** | 法术特效+震动+音效 | 每个按钮有微动效 | 拖拽有弹性动画 | 基础弹跳+颜色 | ⚠️ |
| **音效体系** | 完整BGM+SFX | 独特音效每个操作 | 轻松背景音乐 | 5种基础音效 | ⚠️ |
| **心/命系统** | 无(无限尝试) | 5心+恢复倒计时 | 无惩罚重试 | 3心每日 | ✅ |
| **连击/XP** | 战斗伤害=正确率 | 连胜火焰+宝石 | 星星奖励 | 连击+XP飞行动画 | ✅ |
| **进度展示** | 世界地图探索度 | 关卡进度条+技能树 | 章节完成度 | 知识图谱热力图 | ✅ |
| **个性化** | 自适应难度 | AI题目推荐 | 完全自适应 | 诊断→学习路径 | ✅ |
| **社交元素** | 好友对战/排行榜 | 好友排行榜 | 无 | 无 | ⚠️ |

## 1.2 核心差距总结

### 差距1: 缺少"场景/故事"层 (最严重)
- **竞品**: 答题被包装成战斗(Prodigy)、闯关(Duolingo)、收集(Todo Math)
- **我们**: 纯答题卡片 + 简单进度条
- **影响**: 孩子觉得"在写作业"而非"在玩游戏"

### 差距2: 角色互动单薄
- **竞品**: Avatar可换装、可对话、有性格、在场景中出现
- **我们**: 启小星静态展示，点击只有文字气泡

### 差距3: 答题过程枯燥
- **竞品**: 答题=释放技能、拖拽玩法、连线匹配
- **我们**: 只有选择+填空两种答题方式

### 差距4: 反馈层次不丰富
- **竞品**: 多感官反馈(视觉+听觉+触觉+叙事)
- **我们**: 颜色变化+文字提示

# 第二部分：启明星现有交互流程分析

## 2.1 用户旅程地图

```
首页 → [点击开始诊断] → 诊断页 → [开始诊断] → 题目加载 → 选题/输入
                                                              ↓
                                                         [提交答案]
                                                              ↓
                                                    正确→绿色提示→下一题
                                                    错误→橙色提示→再试/跳过
                                                              ↓
                                                     循环5-10题 → [完成诊断]
                                                              ↓
                                                         诊断报告 → 学习路径 → 单KP练习
```

## 2.2 每个节点的问题分析

### 节点1: 首页
| 要素 | 现状 | 问题 | 严重度 |
|------|------|------|--------|
| 精灵展示 | 静态Canvas动画 | 无引导性交互 | 中 |
| 入口卡片 | 4个纯色渐变卡片 | 无吸引力，无预览 | 高 |
| 统计信息 | 文字数字+进度条 | 不够直观 | 中 |

### 节点2: 诊断流程
| 要素 | 现状 | 问题 | 严重度 |
|------|------|------|--------|
| 开始界面 | 文字+按钮 | 无仪式感 | 高 |
| 题目展示 | 纯文字卡片 | 无公式渲染，无主题 | 严重 |
| 选项按钮 | 固定样式列表 | 无趣味性 | 高 |
| 答题反馈 | 颜色+文字 | 无动画层次感 | 高 |
| 进度指示 | "第X题"文字 | 无视觉进度条 | 中 |

### 节点3: 练习流程
| 要素 | 现状 | 问题 | 严重度 |
|------|------|------|--------|
| 心形系统 | 红心❤️ | 缺少获取/失去动画 | 中 |
| 连击显示 | 彩色文字 | 无爆发力 | 中 |
| XP飞行 | 数字上飘 | 太小太短 | 中 |
| 关卡提示 | Lv标签 | 无解锁/进度感 | 低 |

### 节点4: 诊断报告
| 要素 | 现状 | 问题 | 严重度 |
|------|------|------|--------|
| 报告展示 | 文字列表 | 无可视化 | 高 |
| 学习路径 | 垂直时间线 | 无地图感 | 中 |

## 2.3 答题交互类型分析

现有2种答题方式:

| 类型 | 适用 | 趣味性 | 建议新增 |
|------|------|--------|---------|
| 选择题 | 概念题 | ⭐⭐ | 增加拖拽排序、连线匹配 |
| 填空题 | 计算题 | ⭐ | 增加滑块、数轴、图形拖拽 |

# 第三部分：v2.0 重设计方案

## 3.1 核心设计理念

**"每个知识点都是一个冒险关卡，每次答题都是启小星释放技能"**

## 3.2 主题场景系统

复用已有的8个Storyteller主题，将每个知识点包装成场景关卡:

| 知识点 | 主题 | 场景描述 |
|--------|------|---------|
| 整数运算 | 🚀 太空冒险 | 宇航员启小星收集星星能量 |
| 分数基础 | 🍎 水果店 | 帮启小星经营水果店找零 |
| 百分比 | 🎪 游乐园 | 用奖票兑换游乐设施 |
| 几何 | 🌊 海底世界 | 用形状建造珊瑚礁 |
| 方程 | 🔐 解谜 | 破解密码锁打开宝箱 |

## 3.3 答题交互重设计

### 战斗式答题 (借鉴Prodigy)

```
[怪物出现] → [读题] → [选择答案] → 
正确: 启小星释放技能 → 怪物受伤 → XP飞入 → 过关
错误: 怪物反击 → 掉心 → 提示出现 → 再试
```

### 答题卡重设计

```
┌──────────────────────────────────┐
│ 🎯 整数运算·太空冒险            │  ← 场景标题
│ ┌──────────────────────────────┐ │
│ │  🚀 启小星在太空中遇到了...  │ │  ← 故事化题干
│ │                              │ │
│ │  想收集8颗星星，每颗需要     │ │
│ │  2点能量。小星有15点能量，  │ │
│ │  收完后还剩多少？            │ │
│ └──────────────────────────────┘ │
│                                  │
│  ┌─ A. 1 ─┐  ┌─ B. -1 ─┐       │  ← 选项卡片化
│  └────────┘  └─────────┘       │
│  ┌─ C. 7 ─┐  ┌─ D. 9 ──┐       │
│  └────────┘  └─────────┘       │
│                                  │
│  [本关进度 ████░░░░░░ 40%]      │  ← 关卡进度
├──────────────────────────────────┤
│ 启小星: 💬 "加油，选对了就能   │  ← 角色对话
│          收集到星星！"          │
└──────────────────────────────────┘
```

## 3.4 新增答题交互类型

| 新类型 | 适用场景 | 实现方式 |
|--------|---------|---------|
| 🎯 **射击式** | 选择题 | 选项是"目标"，点击=开火 |
| 🧩 **拖拽排序** | 步骤题 | 把解题步骤拖成正确顺序 |
| 🔗 **连线匹配** | 概念配对 | 左列A右列B连线 |
| 🎚️ **数轴滑块** | 估算题 | 在数轴上滑动到答案位置 |
| 📐 **图形拖拽** | 几何题 | 拖拽角/边到正确位置 |
| 🎰 **转盘式** | 选择题 | 转盘指针转到正确答案 |

## 3.5 动画体系升级

| 动画 | 触发 | 设计 |
|------|------|------|
| **技能释放** | 答对 | 启小星→射线→怪物→爆炸粒子 |
| **受伤反应** | 答错+扣心 | 屏幕震动+红色闪屏+心碎裂 |
| **升级变身** | 精灵进化 | 全身发光+形态变化+旋转特效 |
| **关卡完成** | 通过知识点 | 烟花+星星雨+结算面板划入 |
| **宝箱打开** | 里程碑 | 宝箱晃动→打开→金光+物品弹出 |

## 3.6 音效体系

| 音效 | 触发场景 |
|------|---------|
| 背景音乐 | 不同主题有不同BGM |
| 技能释放音 | 答对时 |
| 受伤音 | 答错时 |
| 升级音 | 精灵进化 |
| 胜利音 | 关卡完成 |
| 收集音 | 获得XP/星币 |
| UI音 | 按钮点击、页面切换 |

# 第四部分：多智能体测试与Review系统

## 4.1 架构

```
用户故事/需求
      │
      ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ Design Agent │ →   │ Code Agent  │ →   │ Test Agent  │
│ (生成设计)   │     │ (编码实现)  │     │ (自动测试)  │
└─────────────┘     └─────────────┘     └─────────────┘
                                             │
                              ┌──────────────┼──────────────┐
                              ▼              ▼              ▼
                       ┌──────────┐  ┌──────────┐  ┌──────────┐
                       │UX Review │  │A11y Review│  │Perf Review│
                       │  Agent   │  │  Agent   │  │  Agent   │
                       └──────────┘  └──────────┘  └──────────┘
                              │              │              │
                              └──────────────┼──────────────┘
                                             ▼
                                    ┌───────────────┐
                                    │ Arbiter Agent │
                                    │ (仲裁+评分)   │
                                    └───────────────┘
                                             │
                                         通过/修改
```

## 4.2 五个Review Agent

### UX Review Agent (用户体验)
- 检查: 交互流程是否连贯、按钮大小是否合适、触控目标≥44px
- 检查: 动画时长是否合适(不应超过400ms)
- 检查: 颜色对比度、文字可读性
- 检查: 每个操作是否有即时反馈

### A11y Review Agent (无障碍)
- 检查: aria-label 是否完整
- 检查: 键盘导航是否可用
- 检查: 屏幕阅读器支持
- 检查: 色彩独立性(不依赖颜色传达信息)

### Perf Review Agent (性能)
- 检查: 首屏加载时间 < 3s
- 检查: 交互响应 < 100ms
- 检查: 动画帧率 ≥ 30fps
- 检查: 内存占用

### Content Review Agent (内容)
- 检查: 题目难度是否合适
- 检查: 题干是否符合目标年龄语言水平
- 检查: 提示是否渐进式
- 检查: 解释是否清晰

### Kid Review Agent (儿童视角)
- 检查: 是否有趣味性
- 检查: 挫败感是否可控
- 检查: 奖励是否及时
- 检查: 主题是否吸引目标年龄段

## 4.3 评分机制

每个Agent对每个交互节点打分(1-10)，Arbiter加权平均:

```
总分 = UX×0.3 + A11y×0.1 + Perf×0.1 + Content×0.2 + Kid×0.3
```

目标: v2.0达到8.0/10

# 第五部分：实施路线

## Phase 1: 答题卡重设计 (优先级最高)
- 故事化题干渲染 (已部署Storyteller API)
- 场景主题选择器
- 公式数学渲染
- 角色对话气泡

## Phase 2: 新增答题交互类型
- 射击式选择题
- 数轴滑块
- 拖拽排序

## Phase 3: 动画体系升级
- 技能释放粒子效果
- 心碎裂动画
- 关卡完成庆祝

## Phase 4: Review Agent系统
- 实现5个Review Agent
- 集成到CI/CD
- 每个PR自动review
