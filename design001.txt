以下是为“ESF数学启明星”（家庭本地验证版）整理的项目启动文档，涵盖设计目标、系统架构、功能模块、测试策略、开发计划及成本估算等全部内容。可直接提供给 OpenCode 团队启动开发。

```markdown
# ESF数学启明星（家庭验证版）项目启动文档

## 1. 项目概述

### 1.1 项目背景
本项目旨在为一名就读于英基（ESF）学校中二（Y8/Y9）的学生构建一套**AI驱动的课后数学辅助系统**，以解决英基体系教学知识点分散、练习熟练度不足，导致学生在升入高年级时出现知识断层和数学学习信心下降的问题。

### 1.2 核心目标
在**仅服务单一家庭、极低成本**的条件下，验证以下四条核心价值是否成立：
- **诊断准确性**：系统能否从孩子答题中自动发现知识断点，并向上追溯到真正的薄弱前置知识？
- **规划合理性**：系统能否基于断点，自动生成“先补A，再练B”的学习路径并清晰说明理由？
- **激励持续性**：成长型数学精灵、连胜、即时奖励等游戏化机制能否让孩子每天主动学习15分钟以上？
- **家长可观可控**：家长端看板能否直观呈现知识图谱掌握度的变化趋势，缓解焦虑并支持决策？

若验证成功，当前架构可不改变核心代码，直接扩展为多用户 SaaS 产品。

### 1.3 参考模式
- **Alpha School**：AI负责知识讲解、个性化练习与进度追踪，人类导师负责情感支持与方向引导。
- **多邻国**：极致碎片化、即时奖励、连胜机制、IP情感化连接。
- **多智能体架构**：诊断、规划、教学、激励四个AI Agent分工协作，基于知识图谱实现精准个性化。

### 2.2 关键设计原则
- 所有 Agent 为独立模块，但部署在同一进程中，通过函数调用协作（MVP阶段无消息队列）。
- 知识图谱使用 NetworkX 加载 JSON 文件，支持 BFS/DFS 追溯断点。
- 数学验证引擎 SymPy 拦截所有AI生成的题目和答案，确保零数学错误。
- 前端采用 PWA 模式，支持手机主屏幕安装、离线缓存、推送通知。
- 数据层全部使用文件和 SQLite，无需独立数据库服务。

## 3. 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | React + Vite + Tailwind CSS | 移动端优先的PWA，支持一屏一题闯关式交互 |
| PWA化 | vite-plugin-pwa | 自动生成 Service Worker 和 manifest |
| 后端 | Python 3.10+ + FastAPI | 异步 API 服务，单进程部署 |
| 知识图谱 | NetworkX + JSON | 内存中构建有向图，持久化至文件 |
| 数据库 | SQLite (通过 SQLAlchemy) | 存储用户答题记录、精灵状态、掌握度 |
| 数学验证 | SymPy | 代数等价性检测、方程求解验证 |
| LLM调用 | OpenAI / DeepSeek API 或 本地 Ollama | 生成题目、讲解、诊断报告文本 |
| 部署 | Gunicorn + Uvicorn + Nginx | 单机部署，HTPPS（Let’s Encrypt），系统守护 |
| 开发工具 | Git, Python venv, Node.js | 版本管理与环境隔离 |

## 4. 功能模块

### 4.1 知识图谱自动构建
- **输入**：IB MYP Y7-Y9 知识点清单、MYP数学指南、参考教材目录
- **流程**：LLM提取知识点→识别前置依赖关系→输出结构化JSON→人工抽检20%
- **产出**：`knowledge_graph.json`（包含节点ID、名称、年级、前置依赖、描述）

### 4.2 题库与讲解自动生成
- **分层练习**：Level 1（基础）、Level 2（变式）、Level 3（拓展·MYP全球背景）
- **生成流程**：LLM生成题目+答案+分步解析 → SymPy验证答案数学正确性 → 人工抽检20% → 存入 `quiz_bank.json`
- **知识点讲解**：LLM生成概念讲解、常见错误提醒、全球背景链接 → 存入 `explanations.json`

### 4.3 诊断Agent
- **功能**：接收学生答题记录（知识点ID+对错） → 在知识图谱中沿`depends_on`边向上游BFS → 综合错误频次和依赖强度输出断点列表及根源分析
- **输出**：断点报告，包含优先级排序和解释

### 4.4 规划Agent
- **功能**：基于断点列表和知识图谱中的依赖拓扑顺序，生成有序的补漏知识点序列
- **输出**：学习路径建议，附带“为什么先学A再学B”的理由文本，推送至家长端审核

### 4.5 教学Agent
- **功能**：从题库和讲解库读取对应内容，组织学习会话；若内容不足，按需触发题目生成
- **交互**：一题一屏，即时判断正误；错误时提供渐进式提示（预设模板+LLM生成）

### 4.6 激励Agent与成长精灵
- **角色**：数学精灵IP，可定制初始形态
- **成长规则**：累计学习天数、正确率、连胜等指标触发形态进化、解锁皮肤和成就徽章
- **即时反馈**：答对得分动画、积分、连胜天数、精灵语音鼓励
- **技术实现**：精灵状态存SQLite，前端CSS动画，PWA推送提醒

### 4.7 家长看板
- **数据展示**：知识图谱掌握度热力图、学习时长统计、知识点掌握度变化曲线
- **规划交互**：查看系统推荐学习路径及理由，可微调优先级后批准执行
- **图形化**：响应式图表，适配手机和电脑

## 5. 测试策略（TDD驱动）

### 5.1 测试金字塔

| 层级 | 测试类型 | 框架 | 覆盖目标 |
|------|---------|------|---------|
| 单元测试 | Agent核心逻辑、规则引擎、数学验证 | Pytest | 覆盖率 >85% |
| 集成测试 | API接口契约、Agent间协作、数据库操作 | Pytest + TestClient | 关键路径全覆盖 |
| 端到端测试 | 完整用户旅程（诊断→规划→学习→激励） | Playwright / Cypress | 主流程 |
| LLM专项测试 | 一致性、安全性、数学准确性金标准测试集 | 自定义脚本 | 200组 ESF典型错例 |

### 5.2 TDD流程示例（诊断Agent）
1. 编写验收测试（Gherkin场景）：`Given 学生在有理数减法错误率40% 且 移项变号错误 …… When 诊断Agent分析 …… Then 输出应关联有理数减法薄弱`
2. 编写单元测试（测试`find_root_causes`函数）
3. 实现功能使测试通过
4. 重构并保持测试全绿

所有功能分支需附带测试，通过CI（GitHub Actions）自动检验，主分支保护。

## 6. 开发计划（共10周）

### 阶段0：预备（第1-2周）
- 技术选型终定，开发环境搭建
- 项目脚手架搭建（FastAPI + React PWA）
- 知识图谱自动生成（LLM辅助，人工审核）产出 `knowledge_graph.json` v0.1
- 编写少量标杆题目，设计LLM出题Prompt模板

### 阶段1：核心闭环 MVP（第3-5周）
**Sprint 1（第3周）**：诊断Agent + 规划Agent 后端实现，API接口
**Sprint 2（第4周）**：题库生成流水线 + 教学Agent核心逻辑（做题、判断、提示）
**Sprint 3（第5周）**：激励Agent基础（积分、连胜）、学生端学习界面（一题一屏）联调
**里程碑**：孩子能完成第一次“诊断→生成练习→做练习→看精灵反馈”完整闭环

### 阶段2：精灵成长与家长看板（第6-8周）
**Sprint 4（第6周）**：精灵进化系统、成就徽章、精灵小屋界面
**Sprint 5（第7周）**：家长看板（知识图谱可视化、学习时长、路径建议展示及微调）
**Sprint 6（第8周）**：端到端联调，真实使用1周，收集反馈调优
**里程碑**：精灵可进化，家长能看懂规划建议，孩子日均使用15分钟

### 阶段3：稳定与文档（第9-10周）
- 性能调优，错误处理加固
- 撰写用户手册（家长/学生）
- 编写架构演进文档（家庭版→多用户版）
- 整理种子用户验证报告

## 8. 成功验收指标

使用一周后，评价下列指标：
- **断点定位准确率**：家长对诊断报告认同度 >80%
- **学习路径采纳率**：家长按规划建议执行率 >80%
- **学生日活跃度**：主动打开应用学习 ≥5天/周
- **连胜留存**：连续学习 ≥3天 现象出现
- **数学自信心**：学生口头反馈正向变化
